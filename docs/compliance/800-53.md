# SP 800-53 Rev 5 crosswalk

This maps cui-guard features and project practices to NIST requirements as evidence. It does not certify, assess or authorize anything.

Catalog: SP 800-53 Rev 5, OSCAL catalog release 5.2.0. IDs and titles were checked against NIST's published catalog on 2026-10-29; see `docs/compliance/README.md` for the source. This is a crosswalk for a customer who maps to 800-53 baselines. It names what the project provides, not what a system achieves.

| Control | Title | What cui-guard contributes | Evidence |
|---|---|---|---|
| AC-4 | Information Flow Enforcement | Inspects outbound agent requests and blocks or pseudonymizes content the policy forbids, subject to the heuristic detection limits in `docs/LIMITS.md`. | `src/cui_guard/pipeline.py`, `src/cui_guard/detect/`, `src/cui_guard/pseudo/egress.py`, `src/cui_guard/policy/`, `tests/leak/`, `tests/redteam/` |
| AU-2 | Event Logging | Logs each gateway decision, including overrides. | `src/cui_guard/audit.py`, `src/cui_guard/override/` |
| AU-3 | Content of Audit Records | Records session, agent, lane, trust level, hit counts, action, blocking rule IDs, request hash, policy hash and override entries, and never the matched value. | `src/cui_guard/audit.py`, `tests/leak/` |
| AU-9 | Protection of Audit Information | Owner-only directory and file modes for the log, and no real values inside it. | `src/cui_guard/audit.py`, `docs/LIMITS.md` |
| SC-7 | Boundary Protection | Loopback-only bind, per-session token, body size cap, header and query scanning, and redirect refusal. | `src/cui_guard/gateway/app.py`, `tests/pentest/`, `tests/fuzz/` |
| SC-8 | Transmission Confidentiality and Integrity | TLS 1.2 or later with certificate verification on the upstream connection. | `src/cui_guard/fips.py`, `tests/test_fips.py`, `docs/FIPS.md` |
| SC-13 | Cryptographic Protection | FIPS mode makes the gateway start only when the platform reports its FIPS provider as active. Customers cite the platform vendor's CMVP certificate. The project is not a validated module. | `src/cui_guard/fips.py`, `tests/fips/`, `docs/FIPS.md`, `tests/security/test_crypto_inventory.py` |
| SI-2 | Flaw Remediation | Dependency audit against two advisory sources, nightly re-audit, dependency update automation and a reporting process. | `scripts/check`, `.github/workflows/nightly.yml`, `.github/dependabot.yml`, `security/vex.cdx.json`, `SECURITY.md` |
| SA-11 | Developer Testing and Evaluation | Leak, pentest, red-team, fuzz, security and FIPS test suites, plus static analysis in CI. | `tests/leak/`, `tests/pentest/`, `tests/redteam/`, `tests/fuzz/`, `tests/security/`, `tests/fips/`, `.github/workflows/codeql.yml`, `docs/SECURITY-ASSURANCE.md` |
| SA-15 | Development Process, Standards, and Tools | One local and CI gate script, pinned workflow actions, workflow linting and secret scanning. | `scripts/check`, `.github/workflows/ci.yml`, `.github/zizmor.yml`, `.gitleaks.toml`, `docs/MAINTAINER-SECURITY.md` |
| SR-3 | Supply Chain Controls and Processes | Locked, hash-pinned dependencies, a short list of runtime dependencies with reasons, and a cooldown on new releases. This covers the project's own dependencies. The customer's supply chain controls for acquiring cui-guard stay theirs. | `uv.lock`, `DEPENDENCIES.md`, `.github/dependabot.yml` |
| SR-4 | Provenance | Release build provenance as GitHub implements SLSA Build Level 2, with no claim beyond that. | `.github/workflows/release.yml`, `docs/SECURITY-ASSURANCE.md` |
| SR-11 | Component Authenticity | Release verification steps, and dismissals of scanner findings only through VEX entries. | `docs/SECURITY-ASSURANCE.md`, `scripts/security/vex.py`, `security/vex.cdx.json`, `.github/workflows/release.yml` |
| CM-8 | System Component Inventory | CycloneDX SBOM generated for each release, covering the cui-guard package and its dependencies. The customer's own system inventory stays theirs. | `scripts/security/sbom.py`, `DEPENDENCIES.md`, `uv.lock` |
